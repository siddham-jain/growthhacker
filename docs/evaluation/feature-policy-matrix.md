# Feature-policy matrix

Generated by `python -m app.evaluation policy render` from the `FeatureSpec` registry (`app/evaluation/policy/features.py`). Do not edit by hand; CI fails when this file and the registry disagree.

Every displayed figure is YouTube API data plus simple maths, labelled 'calculated by GrowthHacker, not a YouTube metric'. Statistical gates are internal filters. There is no composite channel score and no channel ranking. Storing API data past 30 days needs an accepted Section L audit.

## Guardrails

- **G1** API data plus simple maths (counts, sums, medians, means, ratios, sorted lists)
- **G2** never merge YouTube data with other sources into one metric (side by side is fine)
- **G3** no revenue or monetisation estimates
- **G4** no audience demographics, no inferring a video's content category
- **G5** refresh or delete stored API data within 30 days (act at 28)
- **G6** thumbnails: simple traits only, no face recognition

Cells: **OK** complies; **COND** complies under the stated condition; **FLAG** complies by our reading but needs reviewer sign-off; **n/a** guardrail not applicable.

## Needs reviewer sign-off (FLAG)

- **#4 VideoSnapshot time series on batchGetStats** (G5): past view counts cannot be refreshed, so a same-age baseline may only use snapshots under 28 days old; observed day-7 values therefore survive about 35 days after publish. Reviewer to confirm this reading of III.E.4.b, or the Section L audit is needed to keep them up to 36 months.
- **#19 CommentSignals: buyer-question mentions, question count, purchase-intent keywords** (G4): in healthcare (Apollo) comments can reveal a commenter's condition; signals count client-defined buyer questions and intent words only, never a person's health status, and excerpts are off for healthcare and finance. Reviewer to confirm this stays clear of derived-metrics category 4.
- **#25 TopicMatch embedding similarity** (G1): not simple maths on API numbers: it is text matching against the client's own keywords and buyer questions, and the assignment asks for such matching to be flagged. Reviewer to confirm.
- **#26 TopicMatch LLM adjudication** (G1, G4): an LLM decides whether a video is about a client topic (G1), and a model judging aboutness is close to category inference (G4); it is constrained to the client's own ids and every decision is auditable. Reviewer to confirm both cells.
- **#31 Competitor candidate evidence: web mentions, YouTube keyword overlap, ownership verification** (G2): web and YouTube evidence both decide which channels are proposed; they are kept as separate fields behind threshold rules and a human confirms, so no merged number exists. Reviewer to confirm selection by two sources is not a combined metric.
- **#32 Recommendation card ordering: evidence, fit, gap, intent, recency x penalties** (G2): the internal ordering multiplies YouTube evidence with client fit and buyer intent; under D-POL-7 a composite may order cards because it ranks ideas, not channels, and is never shown. Reviewer to confirm.
- **#41 news_opportunity ordering** (G2): news and YouTube demand both influence which news card comes first; ordering is lexicographic with each figure shown separately, so no merged metric exists (D-POL-7). Reviewer to confirm.
